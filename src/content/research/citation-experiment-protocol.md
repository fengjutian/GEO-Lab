本文发布的是可复现的实验协议，结果将作为独立报告发布。截至目前，本文不包含任何已完成观测，也不对"哪个 AI 搜索更愿意引用"给出任何倾向性判断。协议先行公开的目的，是让方法在接受检验之前就固定下来，避免看到数据后再调整口径。

## 研究问题与边界

实验要回答的是一个描述性问题：在查询、时间与内容都受控的条件下，同一篇文章被不同 AI 搜索产品引用的情况是否存在系统差异。这里的"引用"指回答中出现了指向该文章的可识别来源，包括原文摘录、改写后标注来源、以及仅列出链接三种形态。

需要提前划清的边界有三条。第一，实验不测量流量、排名或转化，只测量回答文本层面的引用行为。第二，实验不试图推断任何产品的检索算法，只记录可观察的输出。第三，实验结论只对受测版本与受测问题集成立，不外推为产品的普遍特性。

## 问题集：20 个问题与四层意图

问题集固定为 20 个，按意图分四层，每层 5 个。分层的目的不是追求覆盖全面，而是保证不同意图下的引用行为可以被分开观察，避免把"定义型问题更爱引用"和"某产品更爱引用"混为一谈。

| 意图层 | 数量 | 问题形态 | 观察重点 |
| --- | --- | --- | --- |
| 定义与概念 | 5 | "X 是什么""X 和 Y 的区别" | 是否引用二手解释，还是直接生成 |
| 操作与教程 | 5 | "如何做 X""X 的步骤" | 是否引用步骤型长文的具体段落 |
| 比较与选型 | 5 | "A 与 B 哪个适合…" | 是否引用对比表格或评测结论 |
| 事实核查 | 5 | 带具体数字或时间的问题 | 是否引用含出处的原始陈述 |

问题文本在实验开始前定稿并冻结，任何修改都记为协议变更并说明原因。每个问题同时准备一个同义改写版本，用于检验措辞敏感性，但同义版本不进入主分析，只作为稳健性检查。

## 受测系统与版本记录

受测系统选三个面向公众开放、支持联网检索的 AI 搜索入口。具体产品名在正式报告中披露，协议阶段只约定选择标准：无需申请即可访问、回答中展示来源、在同一地区可用。

版本记录采用"三重锚定"：记录观测日期与时刻、记录产品界面或帮助页中可见的模型标识（若产品不展示，则记为"未披露"）、记录当次会话是否为新建会话。三者缺一不可，因为产品可能在同一天内切换后端模型而不改变界面。

| 记录项 | 取值方式 | 用途 |
| --- | --- | --- |
| 观测时刻 | ISO 8601，精确到分钟 | 对齐时段与索引更新 |
| 模型标识 | 界面可见文案，原样抄录 | 判断版本漂移 |
| 会话状态 | 新建 / 续接 | 排除上下文污染 |
| 登录状态 | 已登录 / 未登录 | 识别个性化影响 |
| 地区与语言 | 出口地区、界面语言 | 说明适用范围 |

## 样本文章的结构变量

样本文章使用同一主题下自撰的三篇技术说明，长度控制在相近区间，内容事实一致，只改变结构。结构变量必须一次只动一个，否则无法归因。

| 变量 | 取值 | 控制方式 |
| --- | --- | --- |
| 结论位置 | 开头摘要 / 文末总结 | 两版正文其余部分逐字相同 |
| 小节粒度 | 长段落 / 每节一个要点 | 小节标题数量不同，总字数相近 |
| 可抽取片段 | 无 / 每节首句为独立结论句 | 仅改首句，不改论据 |
| 数据与出处 | 无 / 关键陈述附来源 | 来源均为公开可核验链接 |
| 结构化元素 | 纯段落 / 含一张表格 | 表格内容与正文一致 |

样本文章存放在独立域名下，不投放广告、不做站内推荐，避免把站点权重差异误读为结构差异。上线时间统一，且在实验开始前留出足够的抓取窗口。

## 记录字段

每条观测记录一行，字段在实验前固定，不允许事后增删。缺失值必须显式记录为"未观察到"，不能用空白代替。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 时间 | 时间戳 | 观测开始与回答完成各记一次 |
| 系统与版本 | 文本 | 产品名 + 模型标识 + 会话状态 |
| 提示词 | 文本 | 原样保存，含标点 |
| 是否引用 | 是 / 否 / 不确定 | 不确定需附截图说明 |
| 引用位置 | 首段 / 中段 / 末尾 / 仅来源列表 | 以首次出现为准 |
| 引用形态 | 摘录 / 改写 / 仅链接 | 可多选 |
| 来源链接 | URL | 记录实际落地页，不记跳转链 |
| 答案准确度 | 1–5 级 | 双人独立打分，分歧复核 |
| 备注 | 文本 | 异常、限流、界面变化 |

## 重复观测与偏差控制

每个"问题 × 系统"单元在同一天内观测三次，分别安排在上午、下午、晚间三个时段，以捕捉索引刷新与流量波动带来的差异。同一时段内的多次请求间隔不少于数分钟，避免触发限流，也避免把缓存结果当成新观测。

账号与地区控制包括：优先使用未登录会话；需要登录时使用两个独立账号交叉验证；固定界面语言与出口地区；每次提问前清空会话历史。问题顺序在每个时段内随机化，减少顺序效应。

评分采用双人独立标注，先各自记录，再比对分歧。分歧超过一档的样本进入复核，复核仍不一致的记为"不确定"，并在报告中单独统计，不并入"是"或"否"。

## 结果不可比因素声明

即使严格执行上述协议，仍有多类因素会让跨系统比较失真，必须在报告中逐条声明，而不是用统计方法掩盖。

第一，检索索引不同。各产品的索引覆盖、更新频率与去重策略不透明，同一篇文章可能只被其中一部分抓取。第二，生成策略不同。摘要长度、引用阈值、是否允许拒答都会改变引用概率。第三，非确定性。相同提示词在同一系统上也可能得到不同回答，单次观测不构成证据。第四，个性化与地域。登录状态、历史行为、出口地区都会影响结果，未登录也不能保证完全中立。第五，产品变更。实验期间的功能更新、A/B 测试与限流都会引入无法控制的变化。第六，"引用"的定义本身存在灰区，来源列表中的一条链接与正文中的整段摘录不应等权。

因此，正式报告只做描述性统计与配对比较，报告每个单元的原始计数与不确定样本比例，不做跨产品的显著性排名，也不把差异归因为产品优劣。

## 局限与后续工作

本协议的主要局限是样本规模小、时间窗口短、只覆盖中文技术类内容，结论的适用范围有限。后续工作包括：把同一协议复用到英文内容与电商、医疗等受监管领域；增加多轮追问场景；在获得授权的前提下，把回答文本与站点的实际引用日志做对照。协议本身的修订将保留版本记录，旧版本不删除，以便读者判断结论是在哪一版方法下得到的。
